DESIGN AND IMPLEMENTATION OF AN ONLINE HYPERMARKET COMMERCIAL CENTERComprehensive 15-Day Implementation Plan — Free Tier Stack (Including Post-MVP Roadmap)Final Year Engineering Project — 20261. PROJECT OVERVIEW AND SCOPEThis document provides the exhaustive, day-by-day implementation plan for building a working online hypermarket mobile application within 15 days. Every tool, service, and library used operates strictly on a free tier. By the end of Day 15, the application will be live, testable by real users, and ready for defense.1.1 Core Features in the MVPUser Authentication: Register, login, logout with JWT. Roles: Customer, Vendor, Admin.Product Catalog: Browse products by category (Groceries, Electronics, etc.). Search and filter.Product Detail Page: Images, description, price, stock status, and customer reviews.Shopping Cart: Persistent cart tied to user account.Checkout and Payment: Stripe test-mode payment.Order Tracking: Customer can view order status: Placed, Processing, Ready, Delivered.Vendor Portal: Vendor can add products, update stock levels, and view incoming orders.Push Notifications: Expo Push Notifications for order status updates.2. Commit to GitHub at the end of every session.Phase 1: Backend Foundation (Days 1-5)Day 1: Project Setup + Auth API- Run `npm init` and install `express mongoose dotenv bcryptjs jsonwebtoken cors multer cloudinary stripe`.- Create free M0 cluster on MongoDB Atlas. Whitelist IP `0.0.0.0/0`.- Write `src/config/db.js` and test MongoDB connection.- Write `User.js` model with `bcrypt` pre-save hook.- Build `auth.controller.js` (register/login) and `auth.middleware.js` (JWT verification). Test in Postman.Day 2: Product API + Cloudinary Integration- Write `Category.js` and `Product.js` models. Add MongoDB text index on Product (`{name: 'text', description: 'text'}`).- Configure `multer` for multipart parsing and `cloudinary.upload_stream` for image hosting.- Build `POST /api/products` for vendors and `GET /api/products` (public) with query parsing (`?search=milk&category=123`).Day 3: Cart, Order, and Vendor API- Write `Cart.js` model. Implement `addItem()` logic to check stock levels before incrementing quantity.- Write `Order.js` model. Implement `placeOrder()`: validates cart, snapshots prices, clears cart, saves order.- Build `GET /api/vendor/products` and `GET /api/vendor/orders` to restrict vendors to their own data.Day 4: Payment API + Push Notifications Backend- Integrate Stripe: build `createPaymentIntent()` returning `clientSecret`.- Set up Stripe Webhook `POST /api/payment/webhook` to update `Order.paymentStatus` to 'paid'.- Build `POST /api/notifications/register` to save Expo push tokens. Integrate Expo SDK push trigger in the order status update controller.Day 5: Backend E2E Testing + Render.com Deployment- Create a full Postman test suite covering the end-to-end flow.- Push backend to GitHub and connect to Render.com Free Web Service.- Configure all Production Environment Variables in Render.- Add Render URL to Stripe Dashboard as the production webhook listener.Phase 2: Mobile App Frontend (Days 6-12)Day 6: Expo Setup + Zustand + Auth Screens- Run `npx create-expo-app hypermarket-app`. Install `expo-router axios zustand @stripe/stripe-react-native`.- Configure `axios` instance with request interceptor to inject JWT from `AsyncStorage`.- Build Zustand `authStore` to manage global login state.- Build `app/(auth)/login.tsx` and `register.tsx`. Set up role-based tab navigation rendering in `_layout.tsx`.Day 7: Home Screen & Catalog Navigation- Build `Home` screen featuring a horizontal `CategoryBar` and `FeaturedProducts` FlatList.- Create `ProductCard` component displaying Cloudinary image URLs and standardizing layout via responsive utilities.- Build dynamic category screen (`app/(customer)/category/[id].tsx`) filtering via API query params.Day 8: Product Details, Reviews, and Cart State- Build Product Details screen with image carousel and 'Add to Cart' functionality.- Implement Zustand `cartStore` to sync local UI state with `PUT /api/cart` requests.- Build `Cart` screen calculating subtotals and allowing quantity adjustments or item removal.Day 9: Checkout Flow & Stripe SDK- Build Checkout screen with toggle for Home Delivery vs. BOPIS (Pickup).- Wrap app layout in `StripeProvider`. Use Stripe `CardField` component.- Implement flow: Call `/api/orders` -> Call `/api/payment/create-intent` -> Call Stripe `confirmPayment()`.Day 10: Customer Orders & Expo Push Handlers- Build Customer Orders list view with color-coded `OrderStatusBadge` components.- Request push notification permissions on app launch. Send token to backend via `/api/notifications/register`.- Set up notification listener to refresh orders list when a push notification is received.Day 11: Vendor Portal & Product Uploads- Build Vendor Dashboard showing active orders and revenue summaries.- Build Add Product screen. Use `expo-image-picker` to select gallery images and transmit via `multipart/form-data`.- Build Vendor Orders screen with dropdowns to update order status (triggering the customer push notifications).Day 12: Admin Dashboard & UI Polish- Build basic Admin screen to list all users and all platform orders.- Conduct a UI polish pass: ensure `ActivityIndicator` spinners are present during all Axios calls.- Implement empty state illustrations (e.g., 'Your Cart is Empty').Phase 3: Integration, Testing and Launch (Days 13-15)Day 13: E2E Integration Testing- Run complete Customer journey: Register -> Browse -> Cart -> Stripe Checkout (using 4242 test card) -> View Order.- Run complete Vendor journey: Login -> Add Product -> Receive Order -> Update Status to 'Delivered'.- Test edge cases: empty cart checkout blocks, expired token redirects to login, offline connection states.Day 14: Bug Fixes, Seed Data, and Expo Go Beta- Write and execute a database seed script (`demo.js`) to generate 3 vendors, 20 products, and 10 sample orders to ensure the app looks fully populated for the defense.- Run `npx expo publish` to generate a project QR code.- Distribute the QR code to testers using Expo Go.Day 15: Final Documentation & Defense Prep- Write the `README.md` detailing the tech stack, API endpoints, and local setup instructions.- Prepare demo test accounts (Customer, Vendor, Admin credentials).- Configure `cron-job.org` to ping the Render backend every 10 minutes to prevent cold starts during the project defense presentation.7.
